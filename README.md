# Radio Player PRO — PWA

Готовый проект Progressive Web App для публикации через GitHub Pages.

## Состав проекта

- `index.html` — плеер и каталог радиостанций.
- `manifest.webmanifest` — название, режим запуска и иконки PWA.
- `service-worker.js` — кеширование оболочки приложения для повторного открытия без сети.
- `icons/` — иконки 192×192 и 512×512, включая maskable.
- `.github/workflows/deploy.yml` — автоматическая публикация GitHub Pages при push в `main`.

## Публикация на GitHub Pages

1. Создайте новый репозиторий на GitHub, например `radio-player-pro`.
2. Загрузите **всё содержимое этой папки** в корень репозитория. Важно: папка `.github` тоже должна попасть в репозиторий.
3. В репозитории откройте **Settings → Pages**.
4. В разделе **Build and deployment → Source** выберите **GitHub Actions**.
5. Откройте вкладку **Actions** и дождитесь успешного запуска `Deploy Radio Player PRO PWA to GitHub Pages`.
6. Адрес будет примерно таким: `https://ВАШ-ЛОГИН.github.io/radio-player-pro/`.

Если репозиторий называется `ВАШ-ЛОГИН.github.io`, адрес будет `https://ВАШ-ЛОГИН.github.io/`.

## Установка на Android

1. Откройте опубликованный HTTPS-адрес в Chrome на Android.
2. Нажмите меню браузера `⋮`.
3. Выберите **Установить приложение** или **Добавить на главный экран**.
4. Подтвердите установку. Плеер появится среди приложений и на главном экране.

Кнопка со стрелкой в шапке плеера также появится, когда Chrome сообщит, что приложение можно установить.

## Что работает без интернета

Service Worker сохраняет локальную оболочку: HTML, манифест и иконки. Поэтому уже открывавшееся приложение может снова показать интерфейс без подключения к сети.

**Радиостанции без интернета не воспроизводятся.** Потоки намеренно не кешируются: они внешние, непрерывные и могут быть защищены CORS/ограничениями серверов.

Избранное, громкость, тема и выбранная станция сохраняются в локальном хранилище браузера.

## Ограничения Android / Bluetooth

PWA использует возможности браузера. События отключения Bluetooth-гарнитуры и переключения аудиовыхода доступны не во всех сочетаниях Android и браузера. Автоматическое возобновление после системной аудиопаузы зависит от того, передаст ли браузер соответствующее событие. Для гарантированного контроля аудиоустройств потребуется нативное Android-приложение.

## Обновление

После изменения файлов отправьте commit в ветку `main`. GitHub Actions опубликует новую версию. При повторном открытии Service Worker скачает обновлённую оболочку; если открытая вкладка продолжает показывать старую версию, перезагрузите её.

## Проверки перед использованием

- Проверьте воспроизведение станций на вашем устройстве и в вашей сети.
- Некоторые потоки могут быть недоступны, менять адреса или ограничивать доступ по региону.
- В браузере должен быть разрешён звук и не запрещено автоматическое воспроизведение после пользовательского нажатия.
